## 0. 文档说明

本方案定义一款离线独立、用户自带 API Key 的角色扮演类 AI 客户端，v1 仅发布 Android 版本。界面风格对齐 DeepSeek 官方移动端，核心能力是自建角色、按角色隔离的长期记忆、超长上下文压缩，并接入官方 API 的图片、文档、联网、语音能力。

- 范围：Android；无自建服务器，数据全部存本地，仅与用户配置的 DeepSeek 官方 API 通信。iOS 暂缓：v1 使用 Kotlin + Compose，不做 iOS 适配、不接内购、不排测试与审核时间；若日后恢复 iOS 再评估 Flutter/KMP。
- 非目标：不是 Agent。不做函数调用、代码执行、文件系统操作和自主多步任务。联网搜索只是官方服务端工具的开关，客户端不执行任何工具。v1 不含 iOS 版本。
- 资料依据：接口信息来自 DeepSeek 官方文档（2026-11-17 查阅）。标注【待验证】的条目，官方文档没有明确说法，需要在 M0 阶段用真实请求确认。

## 2. DeepSeek 接口能力与设计约束

### 2.1 模型对比

| 项目 | deepseek-flash | deepseek-v4-pro |
| --- | --- | --- |
| 版本 | V4.1-Flash-1017 | V4-Pro-0813 |
| 上下文 / 最大输出 | 1M / 384K | 1M / 384K |
| 思考模式 | 支持，默认开启 | 支持，默认开启 |
| 图像理解 | 支持 | 不支持 |
| 文件解析、联网、会话标题 | 官方文档均指定使用 Flash | 文档未说明，按不支持处理【待验证】 |
| 输入（缓存命中），元/百万 tokens | 空闲 0.02 / 高峰 0.04 | 空闲 0.15 / 高峰 0.30 |
| 输入（未命中） | 空闲 1 / 高峰 2 | 空闲 4.5 / 高峰 9 |
| 输出 | 空闲 4 / 高峰 8 | 空闲 13.5 / 高峰 27 |
| 并发上限 | 2500 | 500 |

高峰时段为北京时间周一至周五（不含法定节假日）9:00–12:00、14:00–18:00，其余时段为空闲，空闲价是高峰价的一半。

### 2.2 思考模式与参数

- 开关：`thinking: {type: enabled|disabled}`；强度：`reasoning_effort: low|high|max`。OpenAI SDK 风格下 thinking 需放入 `extra_body`。默认开启，默认强度 high。
- 思考模式下 temperature、top_p 等采样参数不生效。
- 请求不带 tools 时，思维链无需回传，也不会进入后续上下文；带 tools 时必须完整回传 `reasoning_content`，否则返回 400。
- 声明联网工具、开启 safety_check 或 title 时，服务端同样忽略 temperature 等参数。
- 设计结论：创意度滑杆只在“关闭思考、未开联网、未开安全校验”时生效，其余状态置灰并说明原因；title 只在会话首次请求开启。

### 2.3 其他接口约束

- 文档：先传 Files API 解析，再用 file_id 引用。单文件 100 MiB、1000 页；每个请求最多引用 20 个文档，文字合计不超过 8 MiB；解析限时 120 秒；原件和解析结果不可下载；历史中引用的文档会完整保留在后续每轮上下文，超长返回 400，不会静默截断。
- 图片：JPEG、PNG、GIF、WebP，可用 base64 或 file_id。
- TTS：整段 POST 或 WebSocket 流式；音色只有 stella（女）、tide（男）；不能调语速，不能断点续传；单次最多 10,000 计费字符；文本未过审返回 400。
- ASR：16 位 PCM WAV 或 Ogg Opus，最长 120 秒、最大 8 MiB，不支持流式，双声道只识别左声道。
- 工具计费：搜索与网页抓取 5 元/千次；文件解析 1.5 元/千页；TTS 3 元/万字符，ASR 0.78 元/小时（二者当前有限时 5 折）。纯文本、表格、电子书类文件按 user_data 上传不计费。
- 官方合规提示：对外提供应用服务时，需自行承担内容安全审核、大模型登记、AI 标识等义务；官方提供 safety_check 基础风控参数。

## 3. 总体架构

### 3.1 技术选型（库名为候选，M0 验证）

| 领域 | 选型 |
| --- | --- |
| 框架 | Kotlin + Jetpack Compose，原生 Android 单端 |
| 本地库 | Room（SQLite）；FTS5 用原生 SQL 建虚拟表 |
| 敏感存储 | EncryptedSharedPreferences / Android Keystore，存 API Key 与授权状态 |
| 网络 | OkHttp + okhttp-sse，自写事件解析；Files 用 multipart |
| 渲染 | Markwon（Markdown + LaTeX 扩展）+ 代码块样式 |
| 附件 | 系统照片选择器、SAF（ACTION_OPEN_DOCUMENT）、Bitmap 压缩 |
| 音频 | AudioRecord（WAV 16 kHz 单声道）+ Media3 ExoPlayer（变速播放） |
| 密码学 | Tink 或 BouncyCastle（Ed25519、AES-GCM、Argon2id） |
| 其他 | java.util.zip、FileProvider、BiometricPrompt（应用锁） |

### 3.2 分层与模块

- 表现层：页面与组件，主题完全 token 化。
- 领域层：ChatEngine、PromptBuilder、StreamParser、MemoryService、CompactionService、AttachmentService、VoiceService、UsageService、ImportService、BackupService、LicenseService。
- 数据层：Room DAO、FileStore、SecureStore。
- 接口层：DeepSeekClient（chat、files、tts、asr）。
- 硬规则：所有记忆与会话的 DAO 方法必须显式传入 character_id；UI 不直接访问接口层。

### 3.3 提示词装配与缓存策略

DeepSeek 按前缀命中缓存，命中价约为未命中价的 1/50，所以请求结构要保持前缀稳定。固定顺序：

1. system：底层规则（固定文本，含记忆标签协议）
2. 用户档案（仅共享开关开启时）
3. 角色设定
4. 记忆快照（会话开始或压缩后生成并冻结）
5. 历史消息（原样，含 mem 标签）
6. 最新用户消息，末尾附临时“想起”块（不入库）

- 会话进行中不改动第 1–4 项。修改角色设定后会有一次缓存未命中，界面给出提示。
- 切换模型、思考强度、联网开关可能让缓存失效一次【待验证具体影响】，切换时给轻提示。
- 压缩请求把整理指令追加在历史末尾，以复用前缀。

## 4. 数据模型（SQLite）

- character：id、name、avatar_path、summary、persona_text、opening_message、user_persona_text、voice_id、allow_search、bg_override、created_at、updated_at
- persona_history：id、character_id、text、saved_at（保留最近 20 版，可回滚）
- session：id、character_id（非空）、title、model_override、effort_override、pinned、compaction_epoch、created_at、updated_at
- message：id、session_id、role、raw_text（含标签）、display_text、reasoning_text、blocks_json（搜索与引用块）、attachments_json、usage_json、model、status、epoch、compacted、created_at
- attachment：id、message_id、kind、local_path、file_id、purpose、bytes、pages、uploaded_at
- memory：id、character_id、kind、content、importance、emotion_intensity、emotion_tags、status（active / faded / superseded / revoked）、source_message_id、pinned、recall_count、last_recalled_at、superseded_by、created_at
- summary：id、session_id、epoch、text、token_estimate、created_at
- user_profile：display_name、nickname、self_intro、preferences_text、updated_at
- usage_record：ts、session_id、character_id、kind（chat / search / file_parse / tts / asr）、model、input_hit、input_miss、output、search_count、pages、chars、seconds、est_cost_cny、peak
- tts_cache：hash、voice_id、path、bytes、last_used_at
- settings：key、value

约束：character 删除时级联删除其会话、消息、记忆；memory、message 建 FTS5 索引；任何查询不得跨 character_id 读取记忆。

## 5. 角色与会话

### 5.1 角色管理

- 创建、编辑、复制、删除。头像裁成正方形，压缩到 512 px 以内。
- 设定三种输入方式：手动输入、粘贴文本、导入文件。导入支持 txt 与 md，自动识别 UTF-8（含 BOM）与 GBK 编码，上限 200 KB，导入后先预览，再选择“追加”或“替换”。
- 编辑页实时显示设定的 token 估算，超过建议值（默认 8K）给出提醒。
- 修改后下一条消息立即生效，并保存历史版本供回滚。

### 5.2 新建会话

- 唯一入口是选择角色：角色库点“开始对话”，或新建会话时先弹出角色选择。没有角色时引导先创建。
- 开场白作为首条助手消息直接写入，不调用 API。
- 会话列表支持按角色筛选与搜索，可置顶、重命名、删除。
- 标题：Flash 在首次请求开启 title；Pro 下取首条消息前 20 字兜底，可手动修改。若 M0 验证 Pro 支持 title，则与 Flash 一致。

### 5.3 用户档案与共享开关

- 档案由用户手写：称呼、自我介绍、偏好说明。不含任何 AI 写入的记忆。
- 共享开关（设置中，默认关闭）：关闭时，每个角色只使用自己的“用户人设”；开启时，所有角色的 system 中追加同一份档案，角色自己的用户人设仍会追加且优先。

## 6. 对话引擎

### 6.1 发送与流式

- 流程：构建请求 → SSE → 流解析器（分离思考与正文，过滤记忆标签）→ 增量落库 → usage 记账 → 压缩检查。
- 超长上下文下首字等待可能很长：连接超时 30 秒，首字等待不少于 120 秒。
- 切后台或锁屏会断流（Android 后台网络与进程限制）：把已收到内容标为“已中断”，回前台后提供“继续生成”【待验证用前缀续写还是重新请求】。v1 不申请前台服务；若实测断流过于频繁，v1.1 评估生成期间启用前台服务（需常驻通知与通知权限）。
- 429、503 指数退避重试；余额不足（官方常见返回 402）和 Key 无效给出明确提示；400 超长触发紧急压缩。

### 6.2 消息操作

- 复制、停止生成、继续生成、重新生成（可切换版本）、编辑用户消息（截断其后内容并重发）、删除。
- 重新生成、编辑、删除消息时，撤销该消息写入的记忆（status 置为 revoked）。

### 6.3 展示

- 思考过程为可折叠块，流式展示，设置里可隐藏。
- Markdown、代码块、LaTeX 渲染；角色扮演场景下，动作 与（旁白）可选弱化样式。

## 7. 长期记忆系统

### 7.1 设计原则

按角色完全隔离；偏向人的记忆方式（情绪、感悟、关系，而不是纯事实库）；用户可见可控；对缓存友好；无需向量库（1M 上下文足以放下快照）。

### 7.2 记忆类型

| 类型 | 内容 | 衰减 |
| --- | --- | --- |
| user_emotion | 用户当下的情绪与状态、起因 | 半衰期约 3 天 |
| event | 发生了什么、何时、当时的感受 | 约 30 天 |
| self_feel | 角色自己的感受与感悟，第一人称 | 约 14 天 |
| fact | 稳定的事实与偏好 | 约 1 年 |
| promise | 称呼、承诺、待跟进的事 | 不衰减，直到解决或过期 |

重要度 4 以上的记忆，衰减系数下限为 0.5。以上参数均可在配置中调整。

### 7.3 写入协议

- 角色在回复末尾输出 `<mem>` 标签，可为零到多个；格式与示例见附录 A。放末尾而不是开头：开头会让模型先决定记什么再回答，也会拖慢首字。
- 支持三种操作：新增、更新（引用旧记忆 id）、淡忘。
- 记忆以角色第一人称书写并带主观感受，更贴近人的记忆方式。

### 7.4 流解析器

- 状态机逐字符处理：遇到 `<mem` 可能的前缀先暂扣，确认是标签则吞掉直到闭合，否则原样放行。
- 流结束时标签仍未闭合：整段丢弃，不入库、不显示。
- 只解析助手的正文输出，不解析用户输入与思考内容。
- 数据库存原文（含标签，回传给模型以保持格式一致），界面显示过滤后的文本；加载历史时用同一解析器重新生成显示文本，保证一致。

### 7.5 入库与去重

- 单条回复最多入库 3 条，每条不超过 120 字。
- 与已有记忆的字符 n-gram 相似度 ≥ 0.8 时，合并为更新而不是新增。
- 每条记忆记录 source_message_id，用于撤销。

### 7.6 读取与注入

- 记忆快照：默认预算 16K tokens（可调 4K–40K）。按“重要度 × (1 + 情绪强度) × 时间衰减 × 被想起加成”排序，取前若干条，每条带 id，如 `[m12] 事实·重要4：他怕狗，小时候被咬过`。只在新会话开始和压缩后生成，生成后冻结；会话中新写入的记忆已经在历史里，不重复注入。
- 上次分别时的状态：从最近的 user_emotion 与未解决的 promise 拼成一小块，不额外调用 API，让开场能自然接话。
- 临时想起：用最新用户消息做 FTS5 关键词检索，命中已淡忘或超出预算的记忆，附在最新用户消息之后（不入库，上限 2K tokens）。被想起的记忆 recall_count 加一并刷新时间。

### 7.7 记忆管理页

按角色查看；支持筛选、搜索、编辑、删除、置顶，以及把淡忘的记忆“唤回”；可撤销最近写入、一键清空该角色全部记忆。消息旁有一个很淡的“已记住”图标，点开可看内容并撤销，设置里可关闭。

### 7.8 隔离验收

PromptBuilder 构建前断言所有记忆的 character_id 与会话一致；自动化测试覆盖导入、备份恢复、删除级联场景。

## 8. 上下文压缩

### 8.1 触发

- 以最近一次响应 usage 中的输入 token 数为准，加上新增内容的估算。超过阈值（默认约 800K，设置可调 400K–900K，上限 920K）时，在发送下一条消息之前触发。
- 另有手动“整理记忆”入口；API 返回超长错误时紧急触发。
- 不等到 1M：超限请求会失败，输出还要留余量，长上下文的检索质量也会下降。

### 8.2 流程

1. 构造整理请求：system 前缀与历史原样不变，只在末尾追加一条整理指令，从而命中缓存、成本很低。
2. 指令要求输出两部分：(a) 记忆操作标签，侧重当前感悟、情绪、用户状态，仅在确有必要时写入；(b) 会话摘要，包含剧情进展、关系状态、称呼与语气约定、未完事项、近期情绪基调、设定变更。
3. 解析并校验后，用一个事务写入记忆变更、摘要记录并把 compaction_epoch 加一。任何一步失败都不改动历史，稍后重试。
4. 重建发送上下文：system（重新生成记忆快照）+ 摘要消息 + 最近 N 轮原文（默认 30 轮，且不超过窗口的 10%）。
5. 界面插入分隔条“已整理记忆 · 压缩上下文”。原消息全部保留可浏览，仅标记 compacted，不再发送。

### 8.3 细节

- 整理请求的思考强度取用户设置与 high 中较低者，max_tokens 取 16K；请求期间禁用发送并显示进度。
- 失败自动重试两次，仍失败则提示手动重试。
- 当前模型为 Pro 时，历史中的图片与文档按占位文字处理。压缩后附件只在摘要里以文字提及，不再发送原件。
- 整理请求的费用计入用量，并标注为压缩。
- 可选：会话闲置 30 分钟自动整理（默认关闭，因为会消耗 API）。

## 9. 附件：图片与文档（仅 Flash）

### 9.1 可用性与降级

- Pro 下附件按钮置灰，点击提示“deepseek-v4-pro 不支持图片与文档，请切换到 deepseek-flash”。
- 会话里已有附件而切换到 Pro：历史中的图片与文档以文字占位发送，如“[图片：Pro 模式下不可见]”；切回 Flash 恢复原样，因为原件仍在本地。

### 9.2 图片

- 来源：相册、相机、粘贴；每条消息最多 9 张。
- 压缩：长边不超过 2048 px，照片转 JPEG（质量 85），截图保留 PNG，GIF 与 WebP 原样（单张不超过 10 MB）；本地保留原图。
- 发送：小图用 base64 data URL；大图或需要复用的图用 Files API 上传后以 file_id 引用【待验证 file_id 保留期】；detail 默认 auto。

### 9.3 文档

- PDF、Word、PPT：经 Files API 解析，默认“纯文字”方式；用户勾选“含图表”时用图文混排方式，并提示会多耗 token。
- txt、md、csv、json、代码、XLSX、EPUB：以 user_data 方式上传，不计费。
- 上传显示进度；客户端超时设为上传时间加 120 秒解析时间；发送前提示页数与解析费用（1.5 元/千页）。
- 每个请求最多引用 20 个文档，文字合计 8 MiB；超限前给出提示。
- file_id 失效（400）时，用本地原件自动重传。

### 9.4 历史与成本

- 文档内容会随 file_id 完整保留在后续每轮上下文中，成本持续累计。会话页显示“当前上下文含 N 个文档（约 X tokens）”，并允许“移出上下文”（后续请求不再引用，界面保留）。压缩时统一移出。
- 附件只存本地沙盒和用户自己的 DeepSeek 账号，备份时可选是否包含。

## 10. 联网搜索（官方，默认关闭）

- 设置：“联网搜索”开关默认关闭，子项“阅读链接”默认关闭；仅 Flash 可用，Pro 下置灰并标明“不支持”；角色设置中可单独禁止联网。
- 请求：在 tools 中声明 deepseek_web_search（及可选的 deepseek_read_url），是否搜索由模型决定。关闭思考时为普通联网搜索，开启思考时为深度思考搜索（多步搜索，成本更高）。tool_choice 不得指定这两个工具。
- 渲染与回传：渲染搜索卡片（标题、站点、图标）、引用角标和“已搜索 N 个网页”折叠块。服务端返回的内容块原样存库，并按官方要求在后续轮次原样回传；带 tools 时 reasoning_content 的回传规则【待验证服务端工具是否适用】。
- 计费提示：搜索与抓取 5 元/千次，思考模式下一次回复可能触发多次搜索（第三方估计可达约 20 次）。首次开启时提示，用量页单列。
- 角色扮演协调：底层规则要求引用外部信息时保持角色口吻、事实部分如实。

## 11. 语音

### 11.1 朗读（TTS）

- 入口：助手消息上的“朗读”按钮；角色设置里选音色（stella 女声 / tide 男声 / 关闭）和是否自动朗读（默认关闭）。
- 文本预处理：去掉记忆标签、Markdown、emoji、URL、代码块；可选“仅朗读对白 / 朗读全部”，前者去掉 动作 与（旁白）。按句拆分，每段不超过 300 字。
- 播放：v1 整段合成，按段预取并缓存 WAV，实现“准流式”；倍速在播放端实现（官方不支持调语速）。v1.1 改用 WebSocket 流式 PCM（24 kHz、16 位、单声道），降低首句延迟。
- 缓存：以文本加音色的哈希为键，LRU 上限 200 MB。
- 错误：400（内容审核未通过）提示并跳过；429、503 重试；响应中途断开按失败处理。
- 局限：只有两种音色，无法为每个角色定制独特声线，产品文案不要承诺“专属声音”。

### 11.2 语音输入（ASR）

- 交互：按住说话（上滑取消）与点击切换两种；录制 16 kHz、16 位、单声道 WAV，最长 120 秒（110 秒倒计时提示），约 3.8 MB，满足 8 MiB 限制。
- 识别结果填入输入框供编辑，默认不自动发送（可在设置中开启）。语种由服务端自动识别。
- 首次使用时才申请麦克风权限；识别完成后删除录音文件。
- 不支持流式，所以没有实时字幕，用“录音波形 + 识别中”状态代替。

### 11.3 通话模式（P2，v1 不做）

静音检测断句 + 整段 ASR + 流式 TTS 的连续对话。延迟 = 说话结束 + 上传识别 + 模型首字 + TTS 首句，v1 只预留接口。

### 11.4 费用

TTS 3 元/万字符，ASR 0.78 元/小时（均为刊例价，当前限时 5 折），计入用量记录。

## 12. 用量与费用估算

- 数据来源：每次响应 usage 中的输入（缓存命中 / 未命中）、输出、搜索次数；文件解析页数；TTS 字符数；ASR 秒数，写入 usage_record。
- 计价：内置版本化价格表，设置中可手动覆盖并显示价格表日期。高峰与空闲按北京时间判断，并内置法定节假日表（随版本更新），设置提供“强制按高峰 / 空闲估算”。
- 展示：消息级（点击展开输入命中、未命中、输出 tokens 与估算 ¥）；会话页顶部“上下文 xxxK / 1M”进度条；会话、角色、月度汇总与趋势图；可导出 CSV。
- 发送前预估（可选，默认关闭）：根据前缀是否改动预测缓存命中，给出“约 ¥x”，超过阈值（默认 ¥0.5）时提示确认。
- 余额：可选调用官方余额接口显示【待验证当前是否开放】。
- 估算仅供参考，以 DeepSeek 账单为准。

## 13. 个性化界面

### 13.1 风格基线

- 设计 token 化：主色接近 #4D6BFE（需对照官方截图取色）、圆角、间距、字号阶梯；浅色 / 深色两套。
- 助手消息平铺无气泡，用户消息右侧气泡；助手消息上方显示角色头像与名称；底部胶囊输入栏；左侧抽屉放会话列表。
- 不使用 DeepSeek 的名称与 logo；应用名不含 DeepSeek；应用商店与下载页文案写“支持 DeepSeek API”并声明非官方。

### 13.2 背景

- 类型：静态图、GIF、动画 WebP（视频 P2）。
- 作用范围：全局 / 仅会话页 / 按角色覆盖，优先级为角色 > 会话页 > 全局。
- 参数：透明度、模糊（毛玻璃）、遮罩暗度、缩放模式（填充 / 适应 / 居中）、动画暂停；另有气泡透明度、字号、思考块样式。

### 13.3 可读性与性能

- 遮罩层始终存在（可调但有下限），并根据背景平均亮度给出文字色建议。
- 导入时转码：GIF 转动画 WebP，长边不超过 1440 px，帧率不超过 24 fps，文件不超过 30 MB；解码放独立 isolate。
- 切后台、省电模式、键盘弹起、列表快速滚动时暂停动画；低内存设备降级为静态首帧。
- 另含应用锁（生物识别 / PIN）、动效开关。

## 14. 导入官方会话

### 14.1 前置事实

- 网页端导出路径：设置 → 数据管理 → 导出所有历史对话，得到包含会话 JSON 的 zip。手机端是否有入口【待验证】；若没有，可在 Android 手机浏览器登录网页端导出，文件落到本地下载目录。
- 官方导出不包含当时上传的图片与文件（第三方说明）。

### 14.2 向导（强制顺序）

说明页 → 选择或新建角色 → 新建空会话（标记导入中）→ 选择导出文件（zip 或 json）→ 解析预览（标题、时间、条数、模型，可勾选）→ 选择导入方式（每个官方会话对应一个独立会话［默认］/ 合并为一个）→ 可选“让角色阅读并写入记忆”（先显示 token 与费用估算）→ 完成并跳转。

### 14.3 解析与规则

- 流式 JSON 解析放独立 isolate，支持数百 MB 的大文件。字段映射（用户 / 助手 / 思考内容 / 联网块 / 重新生成分支 / 时间戳 / 模型）以真实样本为准，未知字段保留在 raw_extra。
- 分支只导入当前选中的一支。图片与文件缺失时用文字占位。
- 只追加，不覆盖：官方 chat-demo 导入会覆盖已有对话，本应用只追加；以官方会话 id 去重，重复导入时跳过或另存副本。
- 导入的助手消息来自通用助手，标注“来自官方会话”；导入后按所选角色人设继续对话。导入内容计入上下文，超过压缩阈值时导入后立即走压缩与记忆整理。
- 官方开源的 chat-demo（MIT）导入代码作为解析参考，M0 用真实样本核对。

## 15. 备份与恢复

### 15.1 内容与格式

- 包含：角色（含头像、设定历史）、会话与消息、记忆、摘要、用户档案、设置、背景与自定义资源、用量记录；附件原件可选（默认不含）。

### 15.3 恢复

## 17. 合规、隐私与内容责任（非法律意见）

### 17.1 适用性判断

《人工智能拟人化互动服务管理暂行办法》自 2026 年 7 月 15 日起施行，界定看的是功能：模拟自然人人格特征、思维模式和沟通风格的持续性情感互动服务；纯客服、问答等不在范围内。本产品定位为角色扮演，但具备持久角色和情绪记忆，是否落入范围取决于最终形态和监管认定；“纯客户端 + 用户自带 API”是否被视为服务提供者，也没有定论。建议上架前咨询专业人士。商店描述按真实功能如实撰写，不靠措辞规避。

### 17.2 默认采用的低成本措施

- 首次启动 18+ 确认。该办法明确不得向未成年人提供虚拟亲属、虚拟伴侣服务。
- 界面常驻“AI 生成内容”标识。
- 底层规则包含情感边界：不诱导依赖、不贬低现实人际关系；出现自伤等高风险表达时转为关怀并建议寻求现实帮助。
- 连续使用提醒（默认 2 小时，可调、可关）。
- 每个角色支持一键清除全部数据。

### 17.3 内容安全

设置中提供 safety_check 开关（DeepSeek 基础风控，命中返回拒答标识）。开启后 temperature 等参数被忽略，也可能误拦角色扮演内容，默认关闭，是否改为默认开启见第 21 节。

### 17.4 隐私

- 数据全部存本地；唯一外发是用户配置的 DeepSeek API（对话、附件、语音）。首次使用前的同意页明示这一点。
- 无统计 SDK，无云端崩溃上报，日志仅本地且可导出。
- 用户情绪类记忆属敏感个人信息，仅存本地，可见可删。
- API Key 只存 Keystore，不写入备份与日志。
- 相机、相册（Android 13+ 可用系统照片选择器，免存储权限）、麦克风、通知（Android 13+ 运行时授权）按需申请；准备隐私政策与权限说明页。

### 17.5 品牌与内容

不使用 DeepSeek 名称与 logo；用户头像与设定由用户负责，用户协议中声明不得使用侵犯他人肖像权与版权的内容；遵守 DeepSeek 开放平台服务协议。

- 长上下文成本：用户误用长会话可能花费较高，用上下文进度条、阈值提醒和费用估算缓解。
- 合规不确定性：见第 17 节，上架前咨询专业人士。
- 标签泄露：模型可能在正文中输出异常标签格式，解析器需兜底，且不影响显示。
- 性能：动态背景与超长历史渲染，需做列表虚拟化与降级策略。
- 分发与信任：无应用商店渠道时，用户安装与信任成本高，APK 可能被安全软件误报；需下载页、校验和与安装指引。

## 附录 A：记忆标签协议

### A.1 格式

- 新增：`<mem k='event' i='3' e='疲惫,逞强'>我注意到他今天加班后很累，嘴上说没事</mem>`
- 更新：`<mem op='update' id='m12' i='4'>他其实很怕狗，小时候被咬过</mem>`
- 淡忘：`<mem op='fade' id='m7'/>`
- 属性：k 为类型（user_emotion、event、self_feel、fact、promise）；i 为重要度 1–5；e 为情绪标签，可选；id 为快照中给出的记忆编号。

### A.2 底层规则草案（记忆部分）

- 只有在发生值得记住的事时才写，大多数回复不需要写。
- 一条回复最多写 3 条，每条用你自己的第一人称，写下发生了什么和你当时的感受，不超过 120 字。
- 优先记录：对方的情绪与状态、你自己的感悟、关系变化、约定与待跟进的事。
- 记忆标签只放在回复的最末尾，不要在正文中提及或解释标签。
- 对方的情绪与你的看法有变化时，用 update 修正旧记忆，而不是重复新增。

### A.3 解析规则

- 只解析助手正文输出，不解析用户输入与思考内容。
- 属性缺失用默认值（重要度 3）；k 非法则丢弃该条；id 不存在则 update 与 fade 忽略。
- 标签内容为空、超长（超过 120 字）时截断或丢弃，并记录本地日志。
