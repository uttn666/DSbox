# M0 接口验证记录

日期：2026-11-17 · 环境：Windows / curl / 官方 API（用户提供 Key）

## 1. 模型列表 `GET /models`

返回两个模型，字段与方案一致：

| 字段 | deepseek-flash | deepseek-v4-pro |
| --- | --- | --- |
| name | DeepSeek-V4.1-Flash | DeepSeek-V4-Pro |
| context_window | 1048576 | 1048576 |
| max_output_tokens | 393216 | 393216 |
| input_modalities | text, image | text |
| effort.supported_levels | low, high, max | low, high, max |
| effort.default_level | high | high |

结论：模型名、上下文、输出上限、思考强度均已确认；图片输入只有 Flash 支持。

## 2. 流式对话 `POST /chat/completions`

- SSE 帧格式为 `data: {...}`，以 `data: [DONE]` 结束。
- 增量字段：`choices[0].delta.content` 与 `choices[0].delta.reasoning_content` 分开返回，两者都可能是空串。
- 最后一条有 `finish_reason: "stop"` 的 chunk 带 `usage`：
  - `prompt_tokens`、`completion_tokens`、`total_tokens`
  - `prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`
  - `completion_tokens_details.reasoning_tokens`
- 开启思考且任务需要推理时，`reasoning_content` 会持续增量输出；实测一次 144 completion tokens 中有 116 是 reasoning_tokens。
- 只回复“收到”这类简单任务时，思考模式可能直接给出答案，reasoning_tokens 为 0。

## 3. 标题 `title: {"enabled": true}`

- 请求体加 `"title": {"enabled": true}` 生效。
- 标题在最后一个 chunk 的 `delta.title` 返回，与 `finish_reason: "stop"`、`usage` 同一帧。
- 实测返回：“北京明天天气询问”。
- 文档要求只在会话首次请求开启；标题不计费。

## 4. 前缀缓存

短前缀（97 tokens）连续请求 3 次，`prompt_cache_hit_tokens` 始终为 0，说明缓存需要更长的前缀。

长前缀（4817 prompt tokens，约 8000 字符的固定 system）：

| 第几次 | prompt_tokens | cache_hit | cache_miss |
| --- | --- | --- | --- |
| 1 | 4817 | 0 | 4817 |
| 2（12 秒后） | 4817 | 4608 | 209 |
| 3（再 12 秒后） | 4817 | 4608 | 209 |

结论：缓存按 64-token 块命中，长前缀第一次请求后很快可用；方案里“固定 system + 角色 + 快照”的前缀设计成立。会话中修改角色设定、切换模型/强度/联网会让前缀失效一次。

## 5. 余额 `GET /user/balance`

可用，返回 `is_available` 与 `balance_infos[].total_balance`（CNY）。
方案中“可选显示余额”可以实现。

## 6. 错误格式

- 无效模型：HTTP 4xx，body 为
  `{"error":{"message":"The supported API model names are deepseek-flash, deepseek-v4-pro, but you passed ...","type":"invalid_request_error","param":null,"code":"invalid_request_error","request_id":"..."}}`
- 请求体非法（例如非法 UTF-8）：同样返回 `invalid_request_error`。
- 建议客户端统一解析 `error.message`，并按 HTTP 状态码区分 401（Key 无效）、402（余额不足）、429/503（重试）。

## 8. 联网搜索（已实测）

- Chat Completions 请求：`"tools":[{"type":"deepseek_web_search"}]`，可选 `deepseek_read_url`。
- 流式最后一条 chunk 的 `delta` 同时带 `content`、`annotations`（url_citation 列表）与
  `server_tool_calls`（整棵搜索结果树，含 queries、sources、site_icon 等）。
- `usage.server_tool_use` 给出 `tool_search` / `tool_fetch` 次数。
- 注意：角色扮演 system prompt 必须显式允许联网，否则模型会以“我没有联网能力”为由拒绝调用工具。

## 9. Files API（已实测）

- 上传：`POST /files`，multipart，`purpose` 字段必须放在 `file` 之前；
  purpose 取 `text_recognition` / `rich_layout_recognition` / `user_data`。
- 聊天引用（Chat Completions）：`{"type":"file","file_id":"file-api-..."}`，与 text 块同数组。
- 实测 txt 以 `user_data` 上传后，模型能完整读出中文内容并按角色总结。
- 限制：解析类 100 MiB / 1000 页 / 上传与解析各 120 秒；user_data 32 MiB；单请求 20 个文档、文本 8 MiB。

## 10. 图片输入（已实测）

- content 数组：`{"type":"image_url","image_url":{"url":"data:image/jpeg;base64,..."}}`。
- 也可传 `{"type":"file","file_id":"file-api-..."}`。
- 实测 1080×2400 截图压缩后发送，模型能描述截图中的界面与文字。
- 单请求最多 600 张；请求体 48 MiB。

## 11. 语音（已实测）

- TTS：`POST /v1/tools/tts`，JSON `{"text","voice_id":"stella|tide","format":"wav"}`，直接返回 WAV 字节。
- ASR：`POST /v1/tools/asr`，multipart 字段名 `file`，返回 `{request_id,text,duration_ms}`；
  实测 16 秒 WAV 识别成完整中文。
- ASR 不接受流式；录音需 16 kHz/16 bit WAV，最长 120 秒、8 MiB。

## 12. 上下文压缩（低阈值实测）

- 用 300 tokens 的临时阈值触发整理：模型返回 `<mem>` + `<summary>`，摘要 416 字。
- 事务写入 summary、epoch+1、旧消息 compacted=1、插入“已整理记忆”分隔条，并记录
  `usage_record.kind = compaction`。
- 压缩后新请求只带摘要 + 未压缩消息，回复能接上此前剧情。
